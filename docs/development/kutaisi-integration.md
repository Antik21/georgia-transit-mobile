## Что можно выпустить поэтапно

1. **Карта на открытых данных.** Импортировать остановки из OSM и проверить их положение, название и дубликаты. Отобрать городские направления с подтверждённой геометрией и списком остановок. Если подтверждены только остановки, начать с карты и поиска ближайших. Для планирования можно дать ссылку на публичный портал AZRY.
2. **Табло по расписанию и встроенные поездки А → Б.** Когда появится публичное расписание с условиями, подходящими для использования в продукте, сопоставить календарь и времена с упорядоченными остановками каждого направления. Для табло использовать `scheduledAt` и `source=SCHEDULE`, для поездок по расписанию передавать `realtime=false`. Общий граф планировщика можно переиспользовать. Для точных плановых отправлений нужно проверить поддержку расписания в его модели, где сейчас есть `LIVE_VEHICLE` и `HEADWAY_ESTIMATE`.
3. **GPS, прогноз прибытия и оценка риска пересадки.** После появления подходящего публичного потока проверить дневные ответы и покрытие. Для оценки нужны стабильный ID автобуса, связь позиции с направлением и желательно ID рейса и время фиксации. До подтверждения этих полей сохранять время получения снимка отдельно и классифицировать пограничные пересадки по точности наблюдений.

## Контракт и адаптер

- Сохранить текущий BFF `/v1` и общие модели в мобильном клиенте. Формат источника читать в отдельном адаптере `CityTransitProviderAdapter` для `kutaisi`. DTO конкретного поставщика и его параметры доступа остаются внутри BFF. Карта использует `Route`, `Direction`, `Stop`, `Shape` и существующий поиск остановок `/stops/nearby`. [Границы BFF](../../.agents/docs/04-data-bff.md) · [OpenAPI](../openapi/transit-bff-v1.yaml) · [Интерфейс адаптера](../../transitBff/src/main/kotlin/com/denis/georgiatransit/bff/provider/TransitProviderAdapter.kt#L23)
- Формировать стабильные непрозрачные идентификаторы города и поставщика. Связать маршрут с конкретным вариантом направления, порядком остановок и полилинией. Номер линии служит для отображения. Например, одно число может встречаться у городского автобуса, маршрутки или разных вариантов линии.
- Для автобусного `JourneySegment` клиент требует `routeId`, `directionId`, `fromStopId` и `toStopId`. При работе с ответом наподобие AZRY нужно сопоставлять участок с каталогом по варианту и порядку остановок. При подтверждённом сопоставлении использовать существующие `Journey`, `JourneySegment`, `Vehicle` и `Arrival`. [Проверки в мобильном клиенте](../../shared/src/commonMain/kotlin/com/denis/georgiatransit/shared/data/network/TransitBffMappers.kt#L197)
- В `CityCapabilities` включать только подтверждённые функции. Для первого статического выпуска `vehiclePositions`, `arrivals`, `officialArrivals` и `tripPlanning` выключены. `stops`, `routes` и `routeGeometry` зависят от проверенного каталога. [DTO возможностей города](../../transitBff/src/main/kotlin/com/denis/georgiatransit/bff/api/TransitDtos.kt#L15)

### Локальная проверка

Из корня репозитория запустите BFF с примером, в котором включён один город.

```sh
mkdir -p transitBff/build
kutaisi_local="$(mktemp -d "$(pwd -P)/transitBff/build/kutaisi-local.XXXXXX")"
mkdir -m 700 "$kutaisi_local/state"
install -m 600 transitBff/kutaisi-osm-capability-control.example.json "$kutaisi_local/cities.json"

  BFF_KUTAISI_OSM_ENABLED=true \
  BFF_CAPABILITY_CONTROL_PATH="$kutaisi_local/cities.json" \
  BFF_CAPABILITY_CONTROL_STATE_DIR="$kutaisi_local/state" \
  BFF_MAP_ENABLED=true \
  BFF_MAP_TILE_TEMPLATE='https://tile.openstreetmap.org/{z}/{x}/{y}.png' \
```

## Подключение AZRY через BFF

В AZRY-режиме BFF публикует маршруты, направления, геометрию, остановки,
расписание, позиции автобусов и прогнозы по остановкам. Общие экраны читают
возможности выбранного города из `/v1/cities`. Планировщик Кутаиси включается отдельно.
Табло остановки показывает прогнозы AZRY и ближайшее плановое время, когда
приходит строка по расписанию. Полное расписание на дату предоставляется
методом BFF `/v1/cities/{cityId}/routes/{routeId}/directions/{directionId}/schedule?date=YYYY-MM-DD`.
Кнопка «Расписание» на карте доступна для города с `schedules=true`.
На Android и iOS экран читает этот метод при выборе маршрута, направления и даты.
Времена показаны по порядку остановок в местном часовом поясе. Для даты вне
опубликованного календаря экран показывает сообщение об отсутствии расписания.

- Включите `BFF_KUTAISI_AZRY_ENABLED=true`. Передайте `PIS_GATEWAY_KEY` через
  секреты среды BFF. Режимы AZRY и OSM взаимоисключающие.
- Для локальной проверки используйте те же приватные пути документа
  управления и каталога состояния, что указаны выше. Возьмите запись
  из [примера AZRY](../../transitBff/kutaisi-azry-capability-control.example.json).
  Для проверки двух городов добавьте её в документ с Батуми под новой
  ревизией. Сохраните действующие возможности Батуми.
- На рабочем сервере подключение AZRY требует включённого действующего
  schema interlock. Для публикации проверьте разрешённые условия использования
  и лимиты с поставщиком. Код мобильного приложения использует действующую
  тайловую подложку BFF.
- Табло по отдельной остановке использует текущие официальные прогнозы.
  Прогнозы без однозначной привязки к линии пропускаются. Запрошенное
  AZRY время в минутах отсчитывается от получения снимка. Индивидуальные
  отметки времени GPS-фиксации и ID рейса в проверенном ответе отсутствуют.

### Планировщик поездок

В режиме AZRY планировщик ищет прямые варианты и варианты с пересадками по графу
направлений. Остановка посадки и остановка высадки видны в каждом участке. При переходе
на другую остановку показывается пеший участок. Времена ожидания и общая длительность
поездки на автобусе пока неизвестны. Для пешего варианта длительность оценивается по
расстоянию. [ADR 0028](../adr/0028-kutaisi-untimed-journeys.md)

Для включения используйте новую ревизию действующего документа возможностей и задайте
`tripPlanning: true` для Кутаиси в режиме AZRY. Дождитесь сборки графа и проверьте, что
`GET /v1/cities?untimedJourneys=true` возвращает `tripPlanning: true` для Кутаиси.
Обычный `GET /v1/cities` сохраняет совместимость с выпущенными версиями приложения.

### Названия остановок

BFF использует [справочник из 451 остановки](../../transitBff/src/main/resources/transit/kutaisi/stop-names.json).
Грузинские и английские названия, коды и координаты взяты из AZRY. Для остальных
семи языков переведены ориентиры и типы улиц, собственные имена переданы
транслитерацией. Для кодов 132 и 210 версии AZRY расходятся в номерах домов.
В новых переводах этих двух остановок указана улица.

Для карты и остановок направления запись применяется при совпадении публичного
ID и кода, если координаты изменились не более чем на 75 м. В расписании AZRY
передаёт ID и название без кода и координат. Для него BFF сверяет ID и одно из
исходных названий AZRY. При расхождении BFF использует актуальное имя поставщика.
